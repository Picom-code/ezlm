# Install on macOS

EZLM for Mac comes as a disk image, `EZLM.dmg`. You drag the app into Applications and open it. The first time, macOS asks you to confirm that you trust it. This page covers that first open, what to do if EZLM says it is "running from the download", and how to check the install.

## What you need

- macOS 14 Sonoma or later. The app declares 14.0 as its minimum.[^a02-1] To check, open the Apple menu and choose **About This Mac**.
- An Apple Silicon Mac (M1 or later) is recommended: EZLM uses the graphics built into the chip.[^a02-2] Intel Macs work too, but the model runs on the processor and will be slower.[^a02-3]
- Free disk space for the model you pick. Models are often 2 to 60 GB.
- No separate install of the AI engine. It is inside the app.[^a02-4]

## 1. Drag EZLM into Applications

1. Download **EZLM.dmg** and double-click it. A window opens with **EZLM** and an **Applications** folder.
2. Drag **EZLM** onto **Applications**.
3. In Finder, eject **EZLM** (the eject arrow next to its name in the sidebar), then open **EZLM** from **Applications**.

The disk image is built for exactly this: the app plus a shortcut to Applications.[^a02-5] Do not run EZLM from inside the mounted disk image. If you do, macOS runs it from a temporary hidden copy, which is explained in section 3.

## 2. First open: macOS says it cannot check the app

This beta may not be notarized by Apple.[^a02-6] If your copy is not, the first time you open EZLM macOS blocks it and shows a warning that it cannot check the app for malicious software. The wording varies by macOS version. On macOS 14 and later it says **Apple could not verify “EZLM” is free of malware that may harm your Mac or your privacy.** Older versions say the app is from an **unidentified developer**. Both mean the same thing and have the same fix. If your copy is notarized, EZLM opens without this warning and you can skip to section 4.

1. In the warning, click **Done**. Do not click **Move to Trash**.
2. Open **System Settings**, then **Privacy & Security**.
3. Scroll down to the **Security** section. Next to the message about EZLM, click **Open Anyway**.
4. Confirm with your password or Touch ID.
5. macOS shows the warning again. Click **Open**.

From then on EZLM opens normally. This is Apple's standard path for an app that is not notarized, and Apple documents the same steps.[^a02-7]

If there is no **Open Anyway** button, open EZLM from Applications once more. macOS only offers the button after it has blocked a launch. If it is still missing, check that **Allow applications downloaded from** is set to **App Store and identified developers**.

On macOS 15 and later, holding Control and clicking the app no longer offers an **Open** shortcut. Use **Privacy & Security** as above.

## 3. If EZLM says it is "running from the download"

If you open EZLM straight from the disk image, or from your Downloads folder without moving it, macOS runs it from a hidden, read-only copy. This is called App Translocation. EZLM detects it and shows a gold note: **"EZLM is running from the download, so it won't be here after a restart. Drag it into Applications."** with an **Open Applications** button.[^a02-8] EZLM checks both for the hidden location and for a read-only volume.[^a02-9]

EZLM works in this state, but two things are different:

- The copy is temporary. After you quit, the next launch starts again from the original file.
- It cannot update itself in place. The updater writes the new version next to the running app, which fails on a read-only copy, so EZLM opens the disk image in Finder and asks you to drag the new copy over the old one.[^a02-10]

To fix it: quit EZLM, drag **EZLM** from the disk image or Downloads into **Applications**, choose **Replace** if asked, eject the disk image, then open EZLM from **Applications**. The gold note disappears once EZLM is running from Applications.

## 4. Check that it worked

- **Finder.** Open **Applications** and find **EZLM**. Choose **File > Get Info** to see its version.
- **The gold note is gone.** If EZLM still shows "EZLM is running from the download", it is not yet in Applications.
- **The System page.** Open EZLM and choose **System** in the list on the left. You should see **Processor**, **Graphics**, **Engine** and **Storage** lines.[^a02-11] On an Apple Silicon Mac, **Graphics** says "Built into the chip, shares system memory" and **Engine** says "Apple Metal".[^a02-12] On an Intel Mac, **Engine** says "Processor only".[^a02-13]
- **The app's data folders exist.** EZLM keeps its engine and models in `~/.ezlm`[^a02-14] and chat data in `~/Library/Application Support/EZLM`.[^a02-15] Both are created as EZLM needs them, so they may not appear until the first scan or download finishes.

If you want to confirm which copy you are running, open Terminal and run:

```sh
codesign -dv --verbose=2 /Applications/EZLM.app
```

It prints `Identifier=com.ezlm.app` for EZLM.[^a02-16] A build made on your own Mac is signed ad hoc, so it also prints `Signature=adhoc`.[^a02-17] A release build is signed with a Developer ID.[^a02-17]

## 5. If macOS says EZLM is damaged

"EZLM is damaged and can't be opened. You should move it to the Trash" usually means the copy was interrupted or macOS attached the wrong security information to it. Try these in order:

1. Move EZLM from Applications to the Trash, empty the Trash, download `EZLM.dmg` again, and drag EZLM into Applications again.
2. If it still happens, open Terminal and run:

```sh
xattr -dr com.apple.quarantine /Applications/EZLM.app
```

Then open EZLM from Applications. This removes the "downloaded from the internet" mark that macOS puts on the app, so macOS stops checking it on launch.

## If something else goes wrong

Press **Report a problem** in EZLM, or see the troubleshooting guide. The most common macOS problems are a missing **Open Anyway** button and an app that is still running from the download; both are covered above.
