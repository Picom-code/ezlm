# Troubleshooting: page, keys, helper processes, sleep, requirements, version

This section covers the messages produced by `internal/web`, `internal/keys`, `internal/proc`,
`internal/awake`, `internal/prereq` and `internal/version`. Some are shown in the browser page, some
in the app's setup list, and some only reach the log. Each entry gives the exact text, what it means,
and what to do.

A note on where the text appears:

- The browser page shows `internal/web` messages as plain page text or as a red error line.
- `internal/prereq` results appear in the app's setup check list as a name, a detail line and an
  action line (`internal/prereq/prereq.go:26-33`).
- `internal/proc` and `internal/awake` never draw on screen. Their errors are wrapped by the caller
  (usually `internal/integrate`) or written to the log.

## The browser page (`internal/web`)

### 1. `forbidden`

**Message:** `forbidden` (plain page text, HTTP 403)
**Meaning:** The page was opened under a name that is not the exact address EZLM is listening on. EZLM
only answers requests addressed to its own `127.0.0.1:<port>` (`internal/web/server.go:232-237`), which
stops a web page on another site from talking to your local EZLM. Typing `localhost:<port>` instead of
the printed `127.0.0.1:<port>` triggers it, and so does opening the address from another machine.
**Action:** Close the tab and open the Setup page address that EZLM printed, or start EZLM again so it
opens the right one for you.
**Code:** `internal/web/server.go:234` (verified: a request with `Host: localhost:<port>` returns
403 `forbidden`).

### 2. `this page is out of date: reopen EZLM`

**Message:** `this page is out of date: reopen EZLM` (HTTP 401). The page shows it as
`This page is out of date. Close it and open EZLM again.` when the response body has no other error.
**Meaning:** Every EZLM launch makes a new secret and puts it in the page address. A tab left open
from an earlier launch, or a bookmark without the secret, sends an old or missing secret
(`internal/web/server.go:247-260`).
**Action:** Close the tab and start EZLM again, then use the page it opens.
**Code:** `internal/web/server.go:255`; page fallback text `internal/web/static/app.js:20` (verified:
a request with no token, and one with a wrong token, both return 401 with this text).

### 3. A red line with an action's own reason, for example `the disk filled up during the download.`

**Message:** whatever the action reported, as `{"error": "<reason>"}` with HTTP 400
(`internal/web/server.go:262-273`). The page prints that reason in a red line and, during setup, adds
`Stopped` plus a `Back to the start` button (`internal/web/static/app.js:586-592`).
**Meaning:** The request reached EZLM and EZLM refused it. The text is the real reason, passed
through unchanged, so the wording varies by action. A real example is `the disk filled up during the
download. Free about 6 GB and press Set it up again: EZLM resumes where it stopped`
(`internal/app/app.go:744`).
**Action:** Read the reason in the red line and do what it names. If it mentions space, free some
disk. If it mentions a file or folder, choose a different storage folder. If it mentions a port, close
whatever else is using it and try again.
**Code:** `internal/web/server.go:266-269`; `internal/app/app.go:744`.

### 4. `streaming unsupported`

**Message:** `streaming unsupported` (plain page text, HTTP 500)
**Meaning:** The browser connection cannot carry live progress, so EZLM cannot stream setup steps to
the page. It is rare and means the page is being served through something other than the normal
built-in server (`internal/web/server.go:275-280`).
**Action:** Reload the page once. If it comes back, close EZLM, start it again and reopen the page.
**Code:** `internal/web/server.go:278`.

### 5. A startup failure such as `listen tcp 127.0.0.1:0: bind: ...`

**Message:** the operating system's own text, printed by the command line as `ezlm: <text>`
(`cmd/ezlm/main.go:203-206`), or handed to the app in engine mode (`cmd/ezlm/main.go:232-235`).
**Meaning:** EZLM could not open its local port at all, so there is no page. The port is chosen
automatically (`internal/web/server.go:75`), so this points at the system, not at a clash with
another program: too many open connections, a security tool blocking loopback, or a broken network
stack.
**Action:** Restart the computer and try again. If it repeats, allow EZLM in your security software
and report the exact text.
**Code:** `internal/web/server.go:74-83`.

### 6. The page opens but sits on `Processor` forever

**Message:** no error text, the scan list never fills in.
**Meaning:** The page asked for the machine scan and the request did not come back. Because the
page's own request has no time limit, a stuck scan looks like a frozen list
(`internal/web/static/app.js:249-252`, `:263-275`).
**Action:** Wait a minute. If nothing changes, close the page, quit EZLM and start it again.
**Code:** `internal/web/server.go:90-96` (scan endpoint), `internal/web/static/app.js:249`.

## Keys (`internal/keys`)

### 7. `panic: <random source error>`

**Message:** a Go panic, for example `panic: read /dev/urandom: input/output error`
(`internal/keys/keys.go:16-19`).
**Meaning:** The system's random number generator failed while EZLM was making an API key. EZLM
panics rather than hand out a weak key (`internal/keys/keys.go:12-22`). This is very rare and means
the operating system itself is unhealthy.
**Action:** Restart the computer and start EZLM again. If it repeats, report the exact panic text.
**Code:** `internal/keys/keys.go:16-19`.

### 8. A key that looks wrong

**Message:** no message. The key does not start with `ezlm-`, or is shorter than the usual length.
**Meaning:** Every key EZLM makes is `ezlm-` plus 40 letters and digits, about 238 bits
(`internal/keys/keys.go:11-22`). A key without the prefix was typed or copied wrongly, or came from
another tool.
**Action:** Copy the key again with the page's copy button, and paste it whole, with no spaces before
or after.
**Code:** `internal/keys/keys.go:22`.

## Helper processes (`internal/proc`)

These messages reach you only through the feature that ran the helper, usually as part of a longer
sentence such as `the installer stopped with this message: ...` (`internal/integrate/installer.go:69`).
The log holds the full command and output.

### 9. `exec: "<name>": executable file not found in $PATH`

**Message:** `exec: "npm": executable file not found in $PATH`, with the real program name in place
of `npm`.
**Meaning:** The helper program EZLM wanted to run is not installed, or is installed somewhere EZLM
cannot see. This is the start failure from `internal/proc/proc.go:62-64`.
**Action:** Install the program the message names, or reopen EZLM from a normal desktop session so it
sees your usual `PATH`, then try the action again.
**Code:** `internal/proc/proc.go:62-64`.

### 10. `exit status 1`, `exit status 2`, or another number

**Message:** `exit status 1` (the number is the program's own exit code).
**Meaning:** The helper ran and decided to fail. The reason is in its output, which EZLM writes to
the log (`internal/proc/proc.go:77-83`).
**Action:** Open the log from the error line's `Details` and read the last lines of the helper's
output, then follow what that output says.
**Code:** `internal/proc/proc.go:76-83`.

### 11. `signal: killed`

**Message:** `signal: killed`
**Meaning:** EZLM stopped the helper and everything it started, either because you pressed Cancel or
because the step ran out of time (`internal/proc/proc.go:84-88`).
**Action:** Start the action again and let it run without cancelling. If it keeps timing out, close
other programs to free memory and try once more.
**Code:** `internal/proc/proc.go:84-88`.

### 12. `context deadline exceeded` or `context canceled`

**Message:** `context deadline exceeded` (ran out of time) or `context canceled` (you cancelled).
**Meaning:** The step hit its time limit or you stopped it, and EZLM killed the helper's whole process
tree so nothing is left running behind it (`internal/proc/proc.go:1-4`, `:84-88`).
**Action:** Start the action again and leave it alone. If it keeps timing out, use a faster connection
or free disk space first.
**Code:** `internal/proc/proc.go:87`.

### 13. A step that "finishes" while a helper is still running

**Message:** no message.
**Meaning:** Some installers deliberately leave a background service running. EZLM stops reading
their output after 5 seconds and treats the step as done, so a progress line can stop moving while the
service is still starting (`internal/proc/proc.go:47-50`, `:80-82`).
**Action:** Wait a few seconds and reload the page. If the app still shows not connected, use its own
`Check` or `Test` button.
**Code:** `internal/proc/proc.go:50`, `:80-82`.

## Keeping the computer awake (`internal/awake`)

### 14. The computer went to sleep during a download

**Message:** none. `awake` fails silently by design (`internal/awake/awake.go:1-4`, `:11-15`).
**Meaning:** EZLM asks the system to stay awake only while a long job runs. On a Mac it starts
`/usr/bin/caffeinate` (`internal/awake/awake_darwin.go:11-14`), on Linux it starts
`systemd-inhibit` (`internal/awake/awake_linux.go:10-13`), and on Windows it makes a power request
(`internal/awake/awake_windows.go:33-49`). If the tool is missing, or the system refuses, the job
carries on and the computer may sleep. Closing the lid or choosing Sleep still sleeps on purpose.
**Action:** Leave the lid open and avoid choosing Sleep during setup, or change your sleep setting to
a longer time for the download.
**Code:** `internal/awake/awake.go:11-15`; `internal/app/app.go:592`.

## What your machine needs (`internal/prereq`)

The app shows these as a check list. A `fix` item is handled by EZLM. A `fail` item stops setup
until you act (`internal/prereq/prereq.go:19-24`, `internal/app/app.go:646-658`).

### 15. `Not installed. The AI engine needs it.`

**Message:** `Microsoft Visual C++ runtime` / `Not installed. The AI engine needs it.` with the
action `EZLM will install it from Microsoft (Windows asks for permission once).`
**Meaning:** The AI engine's Windows build needs Microsoft's Visual C++ runtime and it is missing
(`internal/prereq/prereq.go:96-98`).
**Action:** Approve the Windows permission prompt when setup offers to install it, and let setup
continue.
**Code:** `internal/prereq/prereq.go:96-98`; installer `internal/prereq/prereq.go:183-194`.

### 16. `Version 14.29.30133 is older than the engine needs (14.51.36247).`

**Message:** `Version <found> is older than the engine needs (<14.51.36247>).` with the action
`EZLM will update it from Microsoft (Windows asks for permission once).`
**Meaning:** The runtime is installed but too old for the engine (`internal/prereq/prereq.go:99-101`).
**Action:** Approve the Windows permission prompt and let EZLM update it.
**Code:** `internal/prereq/prereq.go:99-101`.

### 17. `Couldn't install the Visual C++ runtime: <reason>`

**Message:** `Couldn't install the Visual C++ runtime: <reason>`
**Meaning:** EZLM tried to download and run Microsoft's installer and either the download failed or
the installer failed. Windows needs permission for this, so a dismissed prompt ends up here
(`internal/app/app.go:651-654`).
**Action:** Run setup again and click Yes on the Windows permission prompt. If it repeats, install the
runtime yourself from the link the check list shows and run setup again.
**Code:** `internal/app/app.go:651-654`; `internal/prereq/prereq.go:183-194`.

### 18. `macOS version` / `Update to macOS 13.3 or newer in System Settings > General > Software Update.`

**Message:** detail `macOS 13.1`, action `Update to macOS 13.3 or newer in System Settings >
General > Software Update.`
**Meaning:** The Mac's system version is older than the AI engine supports
(`internal/prereq/prereq.go:109-118`).
**Action:** Update macOS in System Settings > General > Software Update, then run setup again.
**Code:** `internal/prereq/prereq.go:112-116`.

### 19. `Couldn't read the glibc version.`

**Message:** `System libraries (glibc)` / `Couldn't read the glibc version.`
**Meaning:** EZLM could not ask the system which C library version it has. Setup continues with a
warning, because the check is only advice (`internal/prereq/prereq.go:128-131`).
**Action:** Nothing, unless the engine later fails to start. Then open a terminal, run `ldd --version`
and include the first line in your report.
**Code:** `internal/prereq/prereq.go:120-139`.

### 20. `This Linux is too old for the engine (needs glibc 2.38, e.g. Ubuntu 24.04).`

**Message:** `This Linux is too old for the engine (needs glibc <2.34 or 2.38>, e.g. Ubuntu 24.04).`
**Meaning:** The engine's build for your hardware needs a newer C library than this Linux has. The
number is 2.34 for CPU and Vulkan builds, and 2.38 for CUDA and arm64 builds
(`internal/prereq/prereq.go:124-137`).
**Action:** Use a newer Linux release, for example Ubuntu 24.04, and run setup again.
**Code:** `internal/prereq/prereq.go:124-137`.

### 21. `Couldn't read the driver's CUDA version; EZLM will use the Vulkan engine.`

**Message:** `NVIDIA driver` / `Couldn't read the driver's CUDA version; EZLM will use the Vulkan
engine.`
**Meaning:** The graphics card is there but its driver did not report a CUDA version, so EZLM falls
back to the Vulkan engine. Models still run, more slowly (`internal/prereq/prereq.go:149-151`).
**Action:** Update your NVIDIA driver, then scan again. If it still says this, use Vulkan and ignore
it.
**Code:** `internal/prereq/prereq.go:141-164`.

### 22. `Your driver is too old for the CUDA engine, so EZLM uses Vulkan (slower). Update your driver for full speed.`

**Message:** exactly as above.
**Meaning:** The driver reports a CUDA version below 12.4, so the CUDA engine cannot be used
(`internal/prereq/prereq.go:151-153`).
**Action:** Install the current NVIDIA driver and scan again.
**Code:** `internal/prereq/prereq.go:151-153`.

### 23. `Your graphics card needs a newer driver (CUDA 13) for full speed; EZLM uses Vulkan until then.`

**Message:** exactly as above.
**Meaning:** This card's code only ships in the engine's CUDA 13 builds, and the driver is older than
CUDA 13 (`internal/prereq/prereq.go:153-155`, `:166-178`).
**Action:** Install the current NVIDIA driver and scan again.
**Code:** `internal/prereq/prereq.go:153-155`.

### 24. `RTX Spark needs driver 616.41 or newer for the CUDA engine.`

**Message:** exactly as above.
**Meaning:** This RTX Spark card needs at least driver 616.41 for the fast engine
(`internal/prereq/prereq.go:155-157`).
**Action:** Install driver 616.41 or newer from NVIDIA, then scan again.
**Code:** `internal/prereq/prereq.go:155-157`.

### 25. `macOS version: Update to macOS 13.3 or newer in System Settings > General > Software Update.`

**Message:** a setup step line of the form `<check name>: <action>`, for example
`macOS version: Update to macOS 13.3 or newer ...`
**Meaning:** This is how a `fail` check stops setup. EZLM writes the check's name and its action
into the setup log and stops before downloading anything (`internal/app/app.go:656-658`).
**Action:** Do what the action line says, then run setup again.
**Code:** `internal/app/app.go:646-658`.

## Version (`internal/version`)

### 26. `EZLM says it is up to date, but I expected a newer version`

**Message:** no error. The version line reads `EZLM <version>`, for example `0.1.11-beta`
(`internal/version/version.go:5`, shown in `internal/app/app.go:468`).
**Meaning:** The app and the engine ship together and share one version string, so there is no
separate engine version to compare. Update checks compare this string against release tags such as
`v0.1.11-beta` (`internal/version/version.go:3-5`, `internal/app/settings.go:37`). A build made by
hand from source can carry the same string as a release and still say it is up to date.
**Action:** Compare the version on the page with the release you expected. If they differ, run
`ezlm version` and include its output in your report.
**Code:** `internal/version/version.go:5`; `cmd/ezlm/main.go:195-196`.

## Messages worth rewording (for a14)

- `forbidden` (entry 1): says nothing about which address is right. Suggest
  `Open the Setup page at 127.0.0.1, not localhost or another machine.`
- `streaming unsupported` (entry 4): sounds like a browser fault. Suggest
  `The page lost its live connection. Reload it.`
- `context deadline exceeded` / `context canceled` (entry 12): Go words, not English. Suggest
  `The step took too long` and `You stopped the step`.
- `Couldn't read the glibc version.` (entry 19): says nothing to do. Suggest
  `Couldn't check the system libraries. Setup can continue.`
- The `awake` failure (entry 14) has no message at all. Suggest a log line such as
  `Couldn't keep the computer awake during setup.`
