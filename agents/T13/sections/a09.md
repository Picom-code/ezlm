# Server, engine and update messages (a09)

This section documents every message EZLM can show from the part of the program that
runs your model server (`internal/serve`), installs the AI engine and downloads models
(`internal/engine`), and checks for EZLM updates (`internal/update`).

Where you see them:

- **While EZLM sets up a model.** The setup screen lists the steps (engine, model,
  start, load, test). A failed step turns red, and the message is printed under it
  (`windows/EZLM/Install.cs:278`, `macos/Sources/EZLM/AppModel.swift:571`). The panel
  below the steps repeats the message and offers **Report this problem**
  (`windows/EZLM/Install.cs:154`).
- **While you start the server yourself.** Pressing **Start server** on Overview runs
  the same steps, so the same text appears there.
- **In Settings > Updates.** An update check that fails prints one line under the
  version, for example `EZLM 0.1.1. couldn't reach GitHub to check for updates.`
  (`windows/EZLM/SettingsPane.cs:65`). A failed update download prints its message on
  the small line under the update button (`windows/EZLM/SettingsPane.cs:318`).

Text is not translated. Everything in `code font` below is the exact wording, with
`<placeholders>` for the parts that change. A message in brackets at the end, like
`(Get "https://...": dial tcp: ...)`, is the original technical error. Leave it in
when you report the problem: it names the server and the reason.

## Starting and running the model server

### the model server stopped while loading. Last log lines:
```
the model server stopped while loading. Last log lines:
<the last 8 lines of the server log>
```

**What it means:** the model server program quit while it was loading the model, and it
did not write one of the known error lines that EZLM recognises. The usual cause is a
graphics driver that crashes under load, or a start-up flag the build does not accept.
EZLM waits about 13 seconds to be sure (`internal/serve/client.go:90`, `:126`).

**What to do:** if you have an AMD Radeon or Intel Arc card, EZLM retries on the
processor by itself and the setup carries on, so you may only see a gold note about
it. On an NVIDIA card or a Mac, press **Resume and set it up**; if it stops in the same
place, send a report with the log lines. **Stop server**, then **Start server** also
retries without re-downloading.

Code: `internal/serve/client.go:97`, `:122`, `:126`.

### the model did not finish loading in 10m0s. Last log lines:
```
the model did not finish loading in 10m0s. Last log lines:
<the last 8 lines of the server log>
```

**What it means:** the server process stayed alive for ten minutes without answering
`/health`, so EZLM gave up waiting. A very large model on a slow disk, or a model that
barely fits in memory, can take this long (`internal/serve/client.go:105`; the ten
minutes are set at `internal/app/app.go:817`).

**What to do:** press **Start server** on Overview and give it a few more minutes,
since a load that was nearly finished often completes. If it happens again, choose a
smaller model or the **Fastest** preference, and close other apps to free memory.

### the running model server didn't stop. It was probably started with administrator rights, which EZLM can't override: restart your computer, or end "llama-server" in Task Manager, then try again

**What it means:** EZLM asked its server to stop and the server kept its port for ten
seconds. A server started by an administrator, or by another copy of EZLM, cannot be
ended by your normal user account (`internal/serve/config.go:196`, `:201`). This
appears while switching models, changing LAN mode or uninstalling.

**What to do:** restart the computer, or open Task Manager, find `llama-server`, choose
**End task**, then repeat what you were doing.

### EZLM's settings file (<path>) is damaged: <reason>

**What it means:** `config.json` in EZLM's hidden folder cannot be read as JSON. It
holds your key, port, model and engine paths, so EZLM cannot start the server from it.
The path is `C:\Users\<you>\.ezlm\config.json` on Windows and
`~/.ezlm/config.json` on a Mac (`internal/paths/paths.go:10`, `:36`).

**What to do:** set the model up again (Models, then **Set it up**). EZLM writes
a fresh settings file and your model is reused from disk, so nothing is downloaded
twice. The key and port can change, so reconnect OpenCode, Hermes or DeepSeek Harness
afterwards. Keep the old file as `config.json.bak` if you want to report it.

Code: `internal/serve/config.go:61`.

### couldn't open the server log: <reason>

**What it means:** EZLM could not create or open `~/.ezlm/logs/server.log` before
starting the server. A security app that locks the folder, a read-only disk, or a full
disk causes this (`internal/serve/service_windows.go:183`).

**What to do:** check that the disk is not full and that your antivirus allows EZLM's
hidden folder, then press **Start server**. If the file is locked by another program,
restart the computer.

### couldn't start the server: <reason>

**What it means:** Windows accepted the request but the server program did not start.
The common cause is an antivirus or company security app blocking
`llama-server.exe`, or the file being quarantined between the check and the start
(`internal/serve/service_windows.go:200`).

**What to do:** open your antivirus quarantine, restore `llama-server.exe` and allow
EZLM's `bin` folder, then press **Start server**. EZLM downloads the engine again when
the program is missing.

### launchctl bootstrap: <launchctl output>

**What it means:** macOS would not load EZLM's background service. The text is
launchctl's own wording, usually `Bootstrap failed: 5: Input/output error` or a
message that the service is already loaded (`internal/serve/service_darwin.go:35`).

**What to do:** quit EZLM, open it again, and press **Start server**. If it repeats,
log out of your Mac and back in, then try once more and report it if it still fails.

### systemctl <command>: <systemctl output>

**What it means:** Linux's service manager refused the command, for example
`Failed to restart ezlm.service: Unit ezlm.service not found` or `Access denied`
(`internal/serve/service_linux.go:20`).

**What to do:** run `systemctl --user daemon-reload` in a terminal, then press
**Start server** again. If the message says access denied, check that you are logged
in to a desktop session with a user service manager, then report it.

### test request failed: <HTTP status>

**What it means:** the server is running and accepted the request, but the model
answered with an error instead of a reply, for example
`test request failed: 500 Internal Server Error`. The context window being full, or
the model failing on that prompt, produces this (`internal/serve/client.go:184`).

**What to do:** press **Resume and set it up**, which repeats the test. If it fails again,
stop the server, start it, and report with the log lines from Logs.

### test request returned no answer

**What it means:** the reply arrived but contained no choices at all, which means the
server sent an empty response (`internal/serve/client.go:201`).

**What to do:** press **Resume and set it up**. If it happens again, report it with the
server log.

### the model answered with nothing

**What it means:** the model returned an empty answer with no thinking text either.
Some models do this on a short prompt (`internal/serve/client.go:208`).

**What to do:** press **Resume and set it up**, or open **Chat** and ask a question. If
every answer is empty, switch to another model and report it.

### (Your model is thinking out loud and working. Ask it something in the chat.)

**What it means:** not an error. The model produced only thinking text and no final
answer, so EZLM shows this sentence instead of an empty reply box
(`internal/serve/client.go:210`).

**What to do:** ask it something in **Chat**. The model is working; a longer or
clearer question usually gets a final answer.

### A line from the server log, quoted with no prefix

**What it means:** EZLM watches the log for seven known fatal phrases and, when it
finds one, shows that log line as the message, so the text is llama.cpp's own wording
(`internal/serve/client.go:128`, `:134`). The phrases and what they mean:

- `failed to load model` or `error loading model`: the model file is damaged or
  incomplete. Pick the model again so EZLM downloads it again.
- `out of memory` or `failed to allocate`: not enough free memory at that moment.
  Close other apps with **Free up memory**, or choose a smaller model.
- `address already in use` or `couldn't bind`: another program holds the port. EZLM
  usually moves to a free port by itself; if you see this, restart the computer and
  try again.
- `exiting due to`: the server shut itself down. Report the line, since it names the
  reason above it in Logs.

**What to do:** the action depends on the phrase, as listed. Press **Resume and set it up**
after the fix.

### Raw system errors from the server

**What it means:** when nothing more specific applies, the message is the operating
system's own text, for example `open C:\Users\me\.ezlm\config.json: Access is denied.`
or `fork/exec ...: permission denied`. These come from reading the settings, writing
the service file or launching the program, and EZLM passes them through unchanged
(`internal/serve/config.go:62`, `internal/serve/run.go:26`,
`internal/serve/service_darwin.go:82`).

**What to do:** read the path in the message. If it is inside EZLM's folder, allow
that folder in your security app and check the disk is not full, then try again.

## Installing the AI engine

EZLM normally uses a fixed, tested llama.cpp build, so these steps do not ask GitHub
for anything (`internal/engine/pinned.go:3`). The first three messages only appear
when `EZLM_LLAMA=latest` is set.

### could not reach GitHub for llama.cpp: <HTTP status>

**What it means:** EZLM asked GitHub for the newest llama.cpp release and got an error
or a non-200 answer. GitHub allows 60 requests an hour per address, so `403 Forbidden`
often means the limit was reached (`internal/engine/engine.go:60`).

**What to do:** EZLM keeps using the engine already on disk when it can. If there is
none, wait an hour and press **Resume and set it up**, or unset `EZLM_LLAMA` so EZLM uses
its tested build.

### llama.cpp release <tag> has no downloadable builds

**What it means:** the release GitHub calls newest has no program files for any
computer, and no file naming a nightly build (`internal/engine/engine.go:95`). This is
a problem at llama.cpp's end, not on your computer.

**What to do:** unset `EZLM_LLAMA` so EZLM uses its tested build, then press **Set it
up again**. Report the message if it persists.

### no llama.cpp build for <os>/<arch> (<backend>) in release <tag>

**What it means:** the release has no archive matching your operating system,
processor type and graphics backend. EZLM names all three in the message
(`internal/engine/engine.go:189`).

**What to do:** report it with the exact line. As a workaround, choose the **Fastest**
preference, which installs a processor-only build where one exists.

### unpacking <archive>: <reason>

**What it means:** the download finished but could not be unpacked, usually because
the archive is truncated or the disk refused a write (`internal/engine/engine.go:255`).

**What to do:** press **Resume and set it up**. If the same file is named twice, delete it
from EZLM's `bin` folder (`C:\Users\<you>\.ezlm\bin` or `~/.ezlm/bin`) and retry, or
report it.

### llama-server not found in <archive>

**What it means:** the archive unpacked but did not contain the server program. The
build itself is wrong (`internal/engine/engine.go:261`).

**What to do:** press **Resume and set it up** once. If it repeats, report it: EZLM cannot
fix this on your computer.

### checksum mismatch for <file>

**What it means:** the downloaded file's SHA-256 does not match the value GitHub
published, so EZLM deleted it and did not install it (`internal/engine/engine.go:320`,
`:335`; for an EZLM update the same check is at `internal/update/update.go:120`).

**What to do:** press **Resume and set it up**. If it happens twice on the same file, a
proxy or antivirus is altering downloads, so try another network or allow
`github.com` and `huggingface.co`, then report it.

### unsafe path in archive: <name>

**What it means:** an entry in the archive points outside the folder it should unpack
into, so EZLM refused it (`internal/engine/engine.go:341`). This is a damaged or
tampered archive.

**What to do:** press **Resume and set it up**, and report it if it repeats. Do not unpack
the file by hand.

## Downloading a model or the engine

Downloads resume where they stopped, retry five times without progress, and wait 45
seconds for data before cutting a stalled connection
(`internal/engine/download.go:21`, `:78`). The messages below end with the original
technical error in brackets.

### the download keeps stalling (no data arrives for a long time). Check the internet connection and try again: EZLM picks up where it stopped (<error>)

**What it means:** the connection stayed open but delivered nothing for 45 seconds,
five times in a row (`internal/engine/download.go:223`).

**What to do:** press **Resume and set it up**. If it stalls again, try another network
(a phone hotspot is fine), since some networks and VPNs throttle large downloads.

### this computer can't find the download server (<host>), so it looks offline. Check the internet connection and try again: EZLM picks up where it stopped (<error>)

**What it means:** the name of the download server did not resolve, so EZLM cannot
reach it (`internal/engine/download.go:225`).

**What to do:** check that you are online and that no VPN or DNS blocker is running,
then press **Resume and set it up**. Nothing already downloaded is lost.

### the download server's security certificate looks expired, which usually means this computer's date and time are wrong. Set the clock right in your system settings and try again (<error>)

**What it means:** the certificate check failed because it is past its expiry date,
which normally means the computer's clock is wrong
(`internal/engine/download.go:227`).

**What to do:** set the date and time to update automatically, then press **Resume and set it up**.

### something on this network (a security app, antivirus or company proxy) is intercepting secure connections, so the download can't be trusted. Try another network, or allow huggingface.co and github.com in that app (<error>)

**What it means:** the certificate presented for the download does not belong to the
server EZLM asked for, which is what a proxy that inspects traffic looks like
(`internal/engine/download.go:229`).

**What to do:** allow `huggingface.co` and `github.com` in the security app, or
disconnect from the company network and press **Resume and set it up**.

### the connection to the download server keeps dropping. Check the internet connection and try again: EZLM picks up where it stopped (<error>)

**What it means:** connections opened and then broke before any progress, five times
in a row (`internal/engine/download.go:231`).

**What to do:** press **Resume and set it up** and leave it running. A download that keeps
making progress never gives up, so a flaky line still finishes.

### <file> isn't on the download server any more (it may have been moved or renamed). Pick another model, or report this problem

**What it means:** the server answered 404 or 410, and EZLM stopped retrying at once
because a missing file will not come back (`internal/engine/download.go:241`).

**What to do:** pick another model, or the same model at another size. Report it so
the catalog can be corrected.

### the download server won't hand out <file> (it may now need an account). Pick another model, or report this problem

**What it means:** the server answered 401 or 403, which usually means the file now
requires a login or the link has expired (`internal/engine/download.go:243`).

**What to do:** pick another model, or report it. Retrying the same link will not
help.

### downloading <file> failed: <HTTP status>

**What it means:** the server refused the request with a client error other than the
ones above, for example `416` or `451` (`internal/engine/download.go:245`).

**What to do:** report it with the status in the message, then pick another model if
you need to be running quickly.

### the download server is having trouble (<HTTP status>). Try again in a few minutes: EZLM resumes where it stopped

**What it means:** the server answered with a temporary error such as
`503 Service Unavailable`, and EZLM has already retried five times
(`internal/engine/download.go:247`).

**What to do:** wait a few minutes and press **Resume and set it up**. The partial file is
kept and the download continues from there.

### the downloaded file came out the wrong size (<got> bytes instead of <want>), so EZLM deleted it. Try again, and if it happens again, report this problem

**What it means:** the transfer reported success but the file is not the size the
catalog says, so EZLM removed the partial file rather than use it
(`internal/engine/download.go:87`, `:94`).

**What to do:** press **Resume and set it up**, which starts that file from zero. If it
repeats, report it, since it usually means a proxy is rewriting the download.

### the disk filled up during the download. Free about <n> GB and press Set it up again: EZLM resumes where it stopped

**What it means:** the write failed with a disk-full error. EZLM turns that into this
sentence, which is the one place a raw `no space left on device` becomes readable
(`internal/app/app.go:744`).

**What to do:** free the space it names (empty the Trash, remove large files, or move
models to another drive in Settings), then press **Resume and set it up**.

## Updating EZLM

The update check runs when you open Settings, and the result is reused for an hour
(`internal/app/settings.go:36`).

### couldn't reach GitHub to check for updates

**What it means:** the request to GitHub's release list failed outright, so EZLM has
no version to compare against (`internal/update/update.go:67`). On screen the line
reads `EZLM 0.1.1. couldn't reach GitHub to check for updates.` on Windows and
`EZLM 0.1.1. Couldn't reach GitHub to check for updates.` on a Mac, because each app
capitalises the sentence (`windows/EZLM/SettingsPane.cs:66`,
`macos/Sources/EZLM/Settings.swift:296`).

**What to do:** check the internet connection, then press **Check for updates**. Your
model keeps running while you do.

### checking for updates failed (<HTTP status>)

**What it means:** GitHub answered with a non-200 status, for example
`403 Forbidden` when the hourly request limit for your address is used up
(`internal/update/update.go:72`).

**What to do:** wait up to an hour and press **Check for updates**. The rest of EZLM
is unaffected.

### couldn't read the release list

**What it means:** the answer arrived but was not the JSON EZLM expects, usually
because a proxy or security app replaced the page (`internal/update/update.go:89`).

**What to do:** press **Check for updates** once more. If it repeats, allow
`api.github.com` in your security app and report it.

### checksum mismatch for EZLM-Setup-<version>.exe (or .dmg)

**What it means:** the downloaded installer did not match GitHub's published SHA-256,
so EZLM deleted it and did not run it (`internal/update/update.go:120`).

**What to do:** press the update button again. If it repeats, download the installer from
the releases page yourself and run it. Your models are kept.

### Update download messages

The installer download uses the same download code as models, so every message in the
section above can appear here with an installer file name. On Windows the message is
printed on the small line under the update button
(`windows/EZLM/SettingsPane.cs:318`). **What to do** is the same in each case, with
one addition: if the message names a full disk, free space in your temporary folder
as well, since the installer is downloaded there (`internal/update/update.go:112`).

## Messages that are not user-facing

These exist in the three packages but are swallowed before they reach a screen, so a
tester cannot see them. They are listed so the next agent does not re-document them.

- `/props answered <status>` (`internal/serve/props.go:38`): `refreshProps` ignores
  it and keeps the previous values (`internal/app/connect.go:89`).
- Errors from reading the server start time (`internal/serve/client.go:217`) and from
  listing EZLM's own server processes (`internal/serve/procs.go:15`): both fall back
  to a default.
- `the download stopped receiving data` (`internal/engine/download.go:34`): always
  wrapped by the stalling message above.
- `context canceled` (`internal/engine/download.go:63`): the user pressed
  **Cancel**, and the setup screen says `Cancelled` instead.

## Related messages from other packages

Two app-level messages wrap these texts and are worth cross-referencing, because a
tester sees them instead of the original:

- `the model server couldn't start: <reason>` adds the most telling line from the
  server log (`internal/app/app.go:1469`, `:1550`).
- `your model server didn't start: <first line>. Press Start server on Overview to
  try again` is used when connecting an app
  (`internal/app/connect.go:79`).
- `EZLM's model server program is missing and couldn't be restored (<reason>). If an
  antivirus app removed it, allow the folder <path> in that app, then press Start
  server` wraps an engine install failure (`internal/app/app.go:1541`).
