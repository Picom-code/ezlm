# Troubleshooting: machine scan, model fit and the model list

This section covers the messages produced by the code that looks at your computer
(`internal/scan`), the code that decides which model runs well on it
(`internal/fit`), and the model list EZLM ships and updates (`internal/catalog`).

Two things are worth knowing before you read the entries.

First, none of these three parts of EZLM ever stops the app. The scan always
returns a result, and anything it could not read becomes a note or a zero. The
fit code always answers yes or no for each model. The catalog always falls back
to the copy built into the app. So most of the failures below are silent, and
the entry tells you what you see instead of a message.

Second, the notes the scan writes are only printed by the command line program
(`ezlm scan`). The Windows and Mac apps read them but never show them, so a
tester using the app will not see the two "Note" messages below
(`windows/EZLM/Models.cs:28` declares the field, and no app file reads it;
`cmd/ezlm/main.go:376` prints it).

## Entries from the machine scan

### "No supported GPU found: models will run on the CPU, which is slower."

**What it means.** EZLM looked for a graphics card in three ways and found none
it can use: `nvidia-smi` did not answer, `rocm-smi` did not answer, and Windows
did not report an AMD or Intel card that qualifies. Models still run, on the
processor, at a few words per second. The message is written once, in
`internal/scan/scan_other.go:18`.

**What to do.** On an NVIDIA machine, open a terminal and run `nvidia-smi`. If
that command is not found, reinstall the graphics driver from the vendor and
choose the option that adds its tools to the path. On an AMD machine with
Windows, check that the card is listed in Task Manager under Performance. On
Linux with an AMD card, install the ROCm tools so `rocm-smi` exists. Then scan
again.

### "Intel Mac detected: models will run on the CPU."

**What it means.** The Mac has an Intel processor, so there is no shared
graphics memory to use and EZLM does not offer the Metal build. Everything runs
on the processor. The message is written in `internal/scan/scan_darwin.go:12`,
and the scan returns early there, so an Intel Mac also shows no graphics card
at all.

**What to do.** Pick the smallest model in the list and expect slow replies. If
the Mac is Apple Silicon and this message appears, the app was built for the
wrong processor, so download the Apple Silicon build.

### No message: a card is present but EZLM does not list it

**What it means.** A graphics card can be skipped without any message. On
Windows, an AMD or Intel card only counts when its name looks like a discrete
model (Radeon RX, Radeon Pro, Arc A or B) and it has at least 2 GB of its own
memory, or when it is built-in graphics with 8 GB or more set aside. Everyday
built-in graphics are left out on purpose because they are about as fast as the
processor (`internal/scan/gpu_discrete.go:203` to `224`). A card whose driver
entry has no name, or whose driver key cannot be read, is also dropped
(`internal/scan/display_windows.go:49` to `92`).

**What to do.** If the card is real and recent, update its driver, then scan
again. If it is built-in graphics with a small memory share, expect the
processor path and pick a small model.

### No message: the NVIDIA driver is installed but `nvidia-smi` fails

**What it means.** The scan runs `nvidia-smi` and treats any failure as "no
NVIDIA card" (`internal/scan/gpu_discrete.go:15` to `18`). A driver that is
mid-update, a card in a broken power state, or a machine where the tool is not
on the path all end the same way: EZLM carries on to AMD, then to the Windows
display list, and usually ends at the processor.

**What to do.** Run `nvidia-smi` yourself. If it prints a card, scan again. If
it prints an error, reinstall the driver and reboot.

### No message: memory or disk numbers show as zero

**What it means.** Each reading in the scan is best effort. If the memory call
fails, total and free memory stay at zero, and the fit code then assumes a
2 GB reserve for the system (`internal/fit/fit.go:204` to `209`). If the disk
call fails, free space stays at zero, and every model is marked as having
enough room, because a zero free space is read as "unknown" rather than "full"
(`internal/fit/fit.go:321`). `internal/scan/scan.go:280` to `289` has the same
effect for a model folder on a drive that cannot be read: free space comes back
as zero.

**What to do.** Scan again. If the numbers stay at zero, the drive or the
memory reading is being blocked, often by security software, so check that
first. Do not trust the "enough room" claim while the disk figure reads zero.

### "process does not exist"

**What it means.** You asked EZLM to close a program and the program was already
gone by the time the request arrived. The text comes from the process library
EZLM uses, through `internal/scan/scan.go:260` to `262`, and the app shows it
as the note in the close dialog (`windows/EZLM/Shell.cs:495`,
`macos/Sources/EZLM/AppModel.swift:339`).

**What to do.** Nothing is wrong. Scan again to refresh the list.

### "operation not permitted"

**What it means.** The program is running under another user account, or it is
one of the protected programs (the operating system, security software, remote
access, or EZLM itself), so the safety rules refused to close it. The rule is
applied again at close time in `internal/scan/scan.go:264`, and the rules
themselves are in `internal/scan/apps.go:183` to `231`.

**What to do.** Close it yourself from its own window, or leave it open and pick
a smaller model.

### No error: closing a program needs a second, forceful attempt

**What it means.** Closing is gentle first, the same as clicking the window's
close button. A program with no window, or one that ignores the request, comes
back with "needs force" instead of an error
(`internal/scan/apps.go:120` to `122`, `internal/scan/apps.go:154`). The
wording of that prompt belongs to the app, not to this code.

**What to do.** Choose the forceful close, and save your work in that program
first if it has any.

### No message: graphics memory reads zero for a moment after start

**What it means.** On Windows with an AMD or Intel card, the first live reading
of graphics memory starts a background lookup and returns zero until it
finishes (`internal/scan/display_windows.go:113` to `137`). The dashboard can
show zero free for a second or two.

**What to do.** Wait a moment and let the reading catch up. If it stays at zero,
run a scan.

## Entries from the model fit

The fit code has no messages of its own. It answers "yes" or "no" for each
model, and the app turns a "no" into one of the sentences below. All of them
mean the same thing: no arrangement of that model fits in the memory that is
free right now.

### "No model fits in the memory that's free right now. Quit an app on the right, then scan again."

**What it means.** Every model in the list failed. The app builds this sentence
from an empty plan list (`windows/EZLM/Shell.cs:410`); the Mac version says
"No model fits in the memory that's free right now." (`macos/Sources/EZLM/Wizard.swift:190`),
and the command line says "No model fits right now. Close some apps or free
disk space and scan again." (`cmd/ezlm/main.go:384`). The fit code returns
nothing when no quant of no model fits (`internal/fit/fit.go:288` to `293`).

**What to do.** Close the biggest programs in the list on the right, then scan
again. If that is not enough, the machine is below the smallest model EZLM
knows; a machine with 8 GB of memory can still run a small model, so check that
free memory is not near zero before giving up.

### "model \"qwen3.8-27b\" doesn't fit this machine"

**What it means.** You asked for a model by name and it was not in the plan list
from the last scan (`internal/app/app.go:635`). Either it does not fit, or the
scan is older than a memory change.

**What to do.** Scan again, then pick the model from the list instead of by
name.

### "Qwen3.8 27B doesn't fit this machine right now"

**What it means.** You switched to a model that is in the list but has no
working arrangement at this moment, for example because another program took
the free memory since the scan (`internal/app/app.go:1155`).

**What to do.** Close a program, scan again, then switch.

### "Qwen3.8 27B (Q4_K_M) doesn't fit in the memory that's free right now"

**What it means.** The model has other files that fit, but this particular file
does not (`internal/app/app.go:1163`). Larger files of the same model need
more memory.

**What to do.** Pick a smaller file of the same model, which the model list
offers, or close a program first.

### "not enough disk" and "Heads up: this needs about 40 GB and 12 GB is free. Make room now (empty the Trash, remove big files) or the download will pause when the disk fills."

**What it means.** The model fits in memory but not on the drive. Free space
below the download size plus 2 GB marks a plan this way
(`internal/fit/fit.go:321`). A plan is still offered, because you can make room
while it downloads (`internal/fit/fit.go:285` to `287`). The command line shows
"not enough disk" beside the row (`cmd/ezlm/main.go:393`), and the app prints
the longer sentence before it starts downloading (`internal/app/app.go:735`).

**What to do.** Free the space named in the message, then set the model up
again. A download that was interrupted resumes where it stopped.

### No message: a model is offered but marked slow

**What it means.** Plans below 8 words per second are labelled "slow"
(`internal/fit/fit.go:487` to `494`). They are still offered and ranked last
(`internal/fit/fit.go:249` to `257`), so a machine with very little free memory
can still run something. With the "smartest" preference, a plan below 5 words
per second on a graphics card, or 2 on the processor, counts as unusable
(`internal/fit/fit.go:80`).

**What to do.** Expect a long wait for each reply, or pick a smaller model.

## Entries from the model list

### "catalog has no models"

**What it means.** A model list file parsed correctly but contained no models
(`internal/catalog/catalog.go:196`). In practice you only see this in one
place: if the copy built into the app is broken, EZLM stops at startup with
"embedded catalog is invalid: catalog has no models"
(`internal/catalog/catalog.go:161` to `164`). That is a build fault, not
something a tester can cause.

**What to do.** Reinstall the app. If the app starts and the list is simply
empty, report it, because the built-in list is the last fallback and should
never be empty.

### No message: a model list file given by `EZLM_CATALOG` is ignored

**What it means.** Setting `EZLM_CATALOG` to a file path makes EZLM read that
file instead of the built-in list, which is meant for development. If the file
cannot be read, or does not parse, or has no models, EZLM quietly uses the
built-in list (`internal/catalog/catalog.go:149` to `155`). There is no
message either way.

**What to do.** If you set that variable and the list does not change, check
the path and the JSON, or unset the variable.

### No message: the online model list is not used

**What it means.** EZLM tries to fetch a newer model list once, with a four
second limit (`internal/catalog/catalog.go:166`). Offline, behind a firewall,
or on a slow connection, the fetch fails and the built-in list is used. A
fetched list is only accepted when it has models and a higher version number
than the built-in one (`internal/catalog/catalog.go:174`). All of these cases
are silent.

**What to do.** Nothing. The built-in list is complete and correct for this
version. A missing update only means a newer model may not appear yet, so
update the app to get it.

### "embedded catalog is invalid: ..." at startup

**What it means.** The model list compiled into the app could not be parsed, so
there is nothing to fall back to and EZLM stops (`internal/catalog/catalog.go:161`
to `164`).

**What to do.** Reinstall the app, and report the message, because it means the
release itself was built wrong.

## Open questions for the guide lead

  them, or this section should stop calling them messages a tester can see.
- Several fit sentences name the model and the file, and the exact text varies
  with the model. Keep the shape and treat the names as examples.
