# a12. The apps' own messages (Windows and macOS)

This section covers messages the two desktop apps show themselves, meaning the C# app in
`windows/EZLM` and the Swift app in `macos/Sources/EZLM`. Messages that come from the Go engine
and are shown unchanged (for example `Download failed: ...`) are documented in a09 to a11; this
section only adds what the app says around them.

How to read an entry:

- **Where** is the screen or control that shows the text.
- **Means** is what the app is telling the tester.
- **Do** is the next action, in one sentence.
- **Code** is the line that produces the text. `{braces}` mark a part filled in at run time.

A tester who can quote the exact text can be matched to one entry below. Where Windows and macOS
word the same message differently, both versions are given; that drift is listed in the report.
Text described as a toast is the small line at the bottom of the window that fades after about four
seconds (`windows/EZLM/Shell.cs:100-110`, `macos/Sources/EZLM/AppModel.swift:1052-1061`).

## Starting up

### `Something went wrong`
**Where:** full window, instead of the normal first screen (Windows and macOS).
**Means:** EZLM could not finish starting, or a page failed while it was being drawn. The line under
the heading is the specific reason.
**Do:** press Try again first. If the same text comes back, press Report this problem and send it,
or Copy details for support and paste that into a message.
**Code:** `windows/EZLM/Shell.cs:167-175`, `macos/Sources/EZLM/Screens.swift:3-15`

### `EZLM's engine is missing from the app. Reinstall EZLM.`
**Where:** the failure screen above, on the first start.
**Means:** the `ezlm` engine binary that ships inside the app is not where the app expects it. An
antivirus quarantine or an incomplete copy of the app is the usual cause.
**Do:** install EZLM again over the current copy; the tester's models are kept.
**Code:** `windows/EZLM/Engine.cs:54`, `macos/Sources/EZLM/Engine.swift:37`

### `Couldn't start EZLM's engine.`
**Where:** the failure screen, Windows only.
**Means:** Windows refused to start the engine process. This is rare and usually an antivirus or
permissions block.
**Do:** press Try again, and if it repeats, add EZLM to the antivirus allow list and reinstall.
**Code:** `windows/EZLM/Engine.cs:68`

### `EZLM's engine didn't start within 30 seconds. Your antivirus may be scanning it; try again in a moment.`
**Where:** the failure screen, Windows. macOS shows `EZLM's engine didn't start within 30 seconds. Try again in a moment.`
**Means:** the engine was started but did not answer within 30 seconds. A first run on a slow disk
or a real-time antivirus scan is the usual cause.
**Do:** wait a few seconds and press Try again. If it keeps happening, allow EZLM in the antivirus
and try once more.
**Code:** `windows/EZLM/Engine.cs:75`, `macos/Sources/EZLM/Engine.swift:69`

### `EZLM's engine stopped while starting. Your antivirus may have blocked it.`
**Where:** the failure screen, Windows. macOS shows `EZLM's engine stopped while starting.`
**Means:** the engine process exited before it said it was ready. Windows adds the antivirus hint
because a blocked binary is the common cause there.
**Do:** press Try again, then check the antivirus quarantine for `ezlm.exe` and reinstall if it is
listed.
**Code:** `windows/EZLM/Engine.cs:76`, `macos/Sources/EZLM/Engine.swift:76`

### `EZLM's engine sent an address it can't use.`
**Where:** the failure screen, macOS only.
**Means:** the engine started but reported a local address the app could not parse. This is a bug,
not something the tester did.
**Do:** press Try again and then Report this problem so the address reaches the developers.
**Code:** `macos/Sources/EZLM/Engine.swift:90`

### `EZLM's background engine stopped unexpectedly. Your model server keeps running; Try again reconnects to it.`
**Where:** the failure screen, after the app was already open (Windows and macOS).
**Means:** the engine crashed while the window was open. The model server is a separate process and
is still serving the tester's apps.
**Do:** press Try again to reconnect. Chat and model switching are unavailable until it reconnects.
**Code:** `windows/EZLM/Shell.cs:185`, `macos/Sources/EZLM/AppModel.swift:286`

### `This page hit a problem and couldn't be shown.`
**Where:** the body of one section, under its heading, Windows only.
**Means:** one page threw an error while drawing. The rest of the window still works, and the
reason is shown under this line.
**Do:** press Try again, or move to another section and come back. Copy details for support if it
happens on the same page twice.
**Code:** `windows/EZLM/Shell.cs:673-675`

## Setting up or switching a model

### `Setup failed.`
**Where:** the setup or switch screen, under the steps (Windows and macOS).
**Means:** the setup job stopped without giving a reason. This is the fallback; usually the engine
sends a specific line instead, and that line replaces this one.
**Do:** press Back to the start and run the setup again. If the same step fails, use Report this
problem on the same panel.
**Code:** `windows/EZLM/Install.cs:225`, `macos/Sources/EZLM/AppModel.swift:612`

### The line under a failed setup
**Where:** the setup or switch screen, under the red reason. One of four sentences is shown.
**Means:** what state the computer was left in.
**Do:** follow the sentence, then retry.

- `Nothing was changed on your computer except what was downloaded, which is kept for next time.`
  The tester was setting up from the first-run screen. Run the setup again; the download resumes.
- `{model} is back and running, so your apps keep working.` The old model was restored. Connected
  apps keep working while the tester tries again.
- `{model} is back and loading; it'll answer in a minute.` The old model is loading. Wait for
  Overview to say Ready before trying again.
- `Your server is stopped. Press Start server on Overview to bring it back.` Nothing is serving.
  Go to Overview and press Start server.
**Code:** `windows/EZLM/Install.cs:159-162`, `macos/Sources/EZLM/AppModel.swift:649-661`

### `Cancelled. What was already downloaded is kept: it picks up where it stopped next time.`
**Where:** a toast after pressing Cancel during setup (Windows and macOS). When the tester was
switching a model that was already running, a second sentence follows: ` Your model kept running.`
**Means:** the tester stopped the job. Nothing was deleted.
**Do:** start the same model again when ready; the download resumes.
**Code:** `windows/EZLM/Install.cs:210`, `macos/Sources/EZLM/AppModel.swift:592`

### `Make room for this model?`
**Where:** a dialog before setup, Windows only. The body ends with `You can also cancel and free up space yourself.` and the main button is `Make room and continue`.
**Means:** the model does not fit on the disk, so EZLM will remove models the tester is not using,
oldest first, before downloading.
**Do:** press Make room and continue, or Cancel and delete files first. Nothing is removed until
the button is pressed.
**Code:** `windows/EZLM/Install.cs:102-112`

### `No model fits in the memory that's free right now. Quit an app on the right, then scan again.`
**Where:** the model chooser, in place of the model list (Windows and macOS).
**Means:** every model needs more memory than is free at this moment. This is about memory, not
disk, and not about the computer being too small.
**Do:** quit a large app from the list on the right, then press Scan again.
**Code:** `windows/EZLM/Shell.cs:410`, `macos/Sources/EZLM/Wizard.swift:190-191`

## The server on Overview

### `The server couldn't start`
**Where:** the status card on Overview (Windows and macOS). The line under it starts with the
engine's reason.
**Means:** the model server exited while starting. The reason is the engine's own text.
**Do:** press Start server again. On Windows the line ends `Try Start server again; if it keeps
happening, use Copy details for support in Logs.`; on macOS it ends `Try Start server again; if it
keeps happening, report the problem so it can be fixed.`
**Code:** `windows/EZLM/Panes.cs:318-319`, `macos/Sources/EZLM/MainView.swift:303-310`

### `The server is stopped`
**Where:** the status card on Overview, when there is no start error (Windows and macOS).
**Means:** the tester stopped the server, or EZLM did after a failed setup.
**Do:** press Start server. The line under it reads `Apps can't reach your model until you start it again.`
**Code:** `windows/EZLM/Panes.cs:318-322`, `macos/Sources/EZLM/MainView.swift:322`

### `EZLM can't control this server right now`
**Where:** a gold panel at the top of Overview (Windows and macOS).
**Means:** the model server was started by something else with administrator rights, so EZLM can
stop it or switch models only after a restart. It still answers for the tester's apps.
**Do:** restart the computer, or end `llama-server` in Task Manager (Windows) or Activity Monitor
(macOS), and let EZLM start it again.
**Code:** `windows/EZLM/Panes.cs:140-141`, `macos/Sources/EZLM/MainView.swift:237-238`

### `Running on the processor`
**Where:** a gold panel at the top of Overview (Windows and macOS).
**Means:** the graphics card refused the model, so it runs on the processor, which is slower.
**Do:** install a newer graphics driver, then press Try the graphics card again. The panel body
reads `Your graphics card couldn't load this model ({reason}), so it runs on the processor, slower
than it could be. A newer graphics driver may fix this.`
**Code:** `windows/EZLM/Panes.cs:147-151`, `macos/Sources/EZLM/MainView.swift:216-224`

## Chat

### `It didn't answer. Try asking again.`
**Where:** under the tester's message in Chat (Windows and macOS).
**Means:** the reply finished with no text and no error.
**Do:** ask again. If every question does this, check Overview and start the server if it is stopped.
**Code:** `windows/EZLM/Chat.cs:668`, `macos/Sources/EZLM/ChatModel.swift:298`

### `It thought about it but didn't write an answer. Try asking again.`
**Where:** under the tester's message in Chat.
**Means:** the model used its thinking budget and then stopped before writing a reply.
**Do:** ask again, or ask a shorter question.
**Code:** `windows/EZLM/Chat.cs:668`, `macos/Sources/EZLM/ChatModel.swift:298`

### `Couldn't reach your model. It may have stopped: check Overview.`
**Where:** under the tester's message in Chat.
**Means:** the app could not connect to the model server at all.
**Do:** open Overview and press Start server if it is stopped, then ask again.
**Code:** `windows/EZLM/Chat.cs:671`, `macos/Sources/EZLM/ChatModel.swift:306-307`

### `Your model stopped in the middle of answering. Check Overview, then ask again.`
**Where:** under the tester's message in Chat.
**Means:** the connection dropped after the reply started. The partial text is kept.
**Do:** check Overview, start the server if needed, and ask again.
**Code:** `windows/EZLM/Chat.cs:672`, `macos/Sources/EZLM/ChatModel.swift:306`

### `Something went wrong: {details}`
**Where:** under the tester's message in Chat.
**Means:** an unexpected error while reading the reply. The details are the operating system's text.
**Do:** ask again. If it repeats, press Report this problem and include what was being asked.
**Code:** `windows/EZLM/Chat.cs:673`, `macos/Sources/EZLM/ChatModel.swift:309`

### `Your model is still loading. Try again in a moment.`
**Where:** under the tester's message in Chat.
**Means:** the server answered with "loading" or status 503, which happens just after a start or a
model switch.
**Do:** wait for Overview to say Ready, then ask again.
**Code:** `windows/EZLM/ChatStore.cs:253`, `macos/Sources/EZLM/ChatModel.swift:700`

### `The server didn't accept EZLM's key. Restart EZLM; if it keeps happening, report a problem.`
**Where:** under the tester's message in Chat.
**Means:** the app's key and the server's key no longer match, usually after a restart of one but
not the other.
**Do:** quit and open EZLM again. If it repeats, report it.
**Code:** `windows/EZLM/ChatStore.cs:254`, `macos/Sources/EZLM/ChatModel.swift:701`

### `That's more than the model can read at once, even with older messages left out. Try a shorter message or file.`
**Where:** under the tester's message in Chat.
**Means:** the question plus the attached text is larger than the model's context, even after EZLM
drops older turns.
**Do:** send a shorter message, or attach a smaller part of the file.
**Code:** `windows/EZLM/ChatStore.cs:252`, `macos/Sources/EZLM/ChatModel.swift:699`

### `Your model answered with an error ({code}): {message}`
**Where:** under the tester's message in Chat.
**Means:** the server returned an error EZLM has no plain sentence for. The code and message are
shown as the server sent them.
**Do:** ask again. If the same code comes back, copy the line into a problem report.
**Code:** `windows/EZLM/ChatStore.cs:255`, `macos/Sources/EZLM/ChatModel.swift:702`

### Attaching a file to a chat
**Where:** a toast at the bottom of the window when a file is added.
**Means and action, by text:**

- `{name} is too big to attach ({size} MB). Copy in the part you need instead.` The file is over
  2 MB. Paste the relevant part into the message instead.
- `EZLM can't read {name} yet: PDF and Word files need their text copied in.` PDF and DOCX are not
  read yet. Copy the text into the message.
- `{name} isn't a text file, so the model can't read it.` The file is binary. Attach a text file.
- `{name} is about {tokens} tokens: more than {model} can keep in mind ({limit}).` The file is too
  large for the model's context. Attach a smaller part.
- `Couldn't read {name}: {details}` (Windows) or `Couldn't read {name}.` (macOS). The file could
  not be opened, usually because another app has it locked.
**Code:** `windows/EZLM/Chat.cs:1037-1052`, `macos/Sources/EZLM/ChatModel.swift:484-494`

## Connecting and opening apps

### `Couldn't open {app}.`
**Where:** the line under a launch button, and a toast (Windows). macOS shows `Couldn't open it.` in
the same place.
**Means:** the app was installed and connected but did not start. The engine usually supplies a
more specific sentence, which replaces this one.
**Do:** press the launch button again. If it repeats, open the app by hand to check it starts, then
use Report this problem.
**Code:** `windows/EZLM/ReportLaunch.cs:92`, `macos/Sources/EZLM/ReportLaunch.swift:46`

### `Couldn't read the log: {details}`
**Where:** a toast when Show details is pressed on an app tile, Windows only.
**Means:** the app's connection log could not be fetched from the engine.
**Do:** press Show details again. If it repeats, the engine has stopped, so press Try again on the
failure screen.
**Code:** `windows/EZLM/ReportLaunch.cs:129`

### `Hermes needs a 64K context, which {model} can't have on this computer. Switch to a smaller model to use it with Hermes.`
**Where:** the Hermes tile on Connect, in gold (Windows and macOS). The tile cannot be selected
while this is true.
**Means:** the model is too large to reserve a 64K context for, and Hermes requires one.
**Do:** switch to a smaller model, then connect Hermes again.
**Code:** `windows/EZLM/Panes.cs:576`, `macos/Sources/EZLM/AppModel.swift:906`

### `This model can't use tools, so {app} can't edit files with it. Pick a model marked Tools, or use Chat.`
**Where:** the status line on an app tile (Windows and macOS).
**Means:** the connected model does not support tool calling, which OpenCode, Hermes and DeepSeek
Harness need to edit files.
**Do:** pick a model marked Tools in Models, or use the built-in Chat instead.
**Code:** `windows/EZLM/Models.cs:188`, `macos/Sources/EZLM/Models.swift:213`

### `Couldn't open last time` and `The last check failed: {reason}`
**Where:** the status line on an app tile (Windows and macOS).
**Means:** the previous launch of that app failed. The first form is used when the app closed right
after opening; the second carries the check's reason.
**Do:** press the app's button to try again, and use Report this problem if it fails the same way.
**Code:** `windows/EZLM/Models.cs:189`, `macos/Sources/EZLM/Models.swift:215`

### `{app} didn't close.`
**Where:** Model mode, the step for one app, macOS only. Windows asks `Quit {app}?` in a dialog
instead.
**Means:** the app ignored the request to quit, usually because it has an unsaved document.
**Do:** press Try again, or Keep it to move on without closing that app.
**Code:** `macos/Sources/EZLM/ModelMode.swift:134`, `macos/Sources/EZLM/ModelMode.swift:253-257`,
`windows/EZLM/Shell.cs:494`

### `{app} is still running (it may have asked to save something, or it keeps going in the background).`
**Where:** Model mode, the step for one app, macOS only. For a background program the text is
`{app} has no window to close.`
**Means:** the app did not exit on the polite request. The next line reads `Force-closing stops it
right away: anything unsaved in it is lost.`
**Do:** press Force close {app} if the tester has saved their work, or Keep it.
**Code:** `macos/Sources/EZLM/ModelMode.swift:246-251`

## Updates

### `Couldn't start the installer: {details}`
**Where:** the update note in Settings, Windows only.
**Means:** the downloaded installer could not be started. The details are the Windows error.
**Do:** press Update now again. If it repeats, download the installer from the releases page and run
it by hand.
**Code:** `windows/EZLM/SettingsPane.cs:311`

### `The update didn't download.`
**Where:** the update note in Settings (Windows and macOS). `Update cancelled.` appears instead if
the tester stopped it.
**Means:** the update job ended without a downloaded file and without a more specific reason.
**Do:** press Update now again; a partial download resumes.
**Code:** `windows/EZLM/SettingsPane.cs:319`, `macos/Sources/EZLM/Settings.swift:56`

### `The update downloaded, but EZLM can't find the file. Try again.`
**Where:** the update note in Settings, macOS only.
**Means:** the download finished but the disk image is not at the path the engine reported.
**Do:** press Update now again.
**Code:** `macos/Sources/EZLM/Settings.swift:74`

### `Drag EZLM into Applications to replace the old one, then open it again.`
**Where:** the update note in Settings, macOS only, after the automatic install failed.
**Means:** the app could not replace itself in place, usually because it is not in Applications or
the folder is not writable. The downloaded disk image is opened in Finder so the tester can drag.
**Do:** drag EZLM from the open window into Applications and confirm Replace, then open EZLM again.
**Code:** `macos/Sources/EZLM/Settings.swift:96-101`, reason logged by
`macos/Sources/EZLM/Updater.swift:21-58`

### `Installed. Quit EZLM and open it again to finish.`
**Where:** the update note in Settings, macOS only.
**Means:** the new app is in place but the automatic restart could not be arranged.
**Do:** quit EZLM and open it again from Applications.
**Code:** `macos/Sources/EZLM/Settings.swift:88-91`

### `Demo: the update downloaded, but nothing is installed in demo mode.`
**Where:** a toast in Settings when the app runs with `--demo`, macOS only. Windows demo mode has no
update path.
**Means:** demo builds do not install updates.
**Do:** nothing; this is expected in a demo.
**Code:** `macos/Sources/EZLM/Settings.swift:70-72`

### `EZLM is running from the download, so it won't be here after a restart. Drag it into Applications.`
**Where:** a gold bar at the top of the window and in the first-run screens, macOS only.
**Means:** the app is running from the disk image or from a translocated copy in Downloads. It works
but will not survive a restart and cannot update itself.
**Do:** press Open Applications and drag EZLM into that folder.
**Code:** `macos/Sources/EZLM/Settings.swift:424-437`, `macos/Sources/EZLM/Wizard.swift:100`,
`macos/Sources/EZLM/MainView.swift:146`

## Settings and model storage

### `Couldn't change where models are saved.`
**Where:** a toast in Settings, Windows only.
**Means:** the storage move or save job failed without a more specific line.
**Do:** try Save again, and pick a folder on a disk with enough free space.
**Code:** `windows/EZLM/SettingsPane.cs:237`

### `Couldn't open the folder picker: {details}`
**Where:** a toast in Settings, Windows only.
**Means:** the Windows folder dialog could not open.
**Do:** press Choose a folder again. If it repeats, restart EZLM.
**Code:** `windows/EZLM/SettingsPane.cs:216`

### `Models are already saved there.`
**Where:** a toast in Settings, macOS only.
**Means:** the chosen folder is the one already in use, so nothing was moved.
**Do:** nothing; pick a different folder if a move was intended.
**Code:** `macos/Sources/EZLM/Settings.swift:170`

## Reporting a problem

### `Couldn't send the report: {details}`
**Where:** a toast on the report form (Windows and macOS). macOS shows this only when the GitHub
page could not be filled in either.
**Means:** the engine could not take the report and the fallback page could not be built.
**Do:** copy the text of the report and send it to the tester's contact by hand.
**Code:** `windows/EZLM/ReportLaunch.cs:206`, `macos/Sources/EZLM/ReportLaunch.swift:252`

### `Your report is filled in on GitHub: press Submit there to send it.`
**Where:** a toast after pressing Send on the report form (Windows and macOS).
**Means:** the engine could not post the report itself, so a browser page was opened with the text
filled in. Nothing is sent until Submit is pressed.
**Do:** press Submit in the browser tab, then close it.
**Code:** `windows/EZLM/ReportLaunch.cs:203`, `macos/Sources/EZLM/ReportLaunch.swift:243`

### `Sent. Thank you! (report #{number})`
**Where:** a toast after pressing Send on the report form (Windows and macOS).
**Means:** the report reached the server. The number identifies it in a follow-up message.
**Do:** nothing.
**Code:** `windows/EZLM/ReportLaunch.cs:199`, `macos/Sources/EZLM/ReportLaunch.swift:238`

## Messages that appear only in the log

Some failures have no on-screen text of their own; the app writes them to its log and shows a
generic line instead. Testers who press Copy details for support include the log.

- macOS update install reasons: `EZLM isn't running from an app ({path})`, `The update doesn't
  contain EZLM.app`, `The update is a different app ({id})`, and `{tool} failed: {output}`. The
  screen shows `Drag EZLM into Applications...` for all of them.
  **Code:** `macos/Sources/EZLM/Updater.swift:21-58`
- Engine and page errors on Windows go to `%LOCALAPPDATA%\EZLM\app.log`; on macOS they go to the
  in-app log shown under Logs. **Code:** `windows/EZLM/Shell.cs:192-204`,
  `macos/Sources/EZLM/AppModel.swift:1025`

## Notes for the assembler

- Every entry has the three parts in the order message, meaning, action.
- The two apps share most sentences word for word. The exceptions are listed in
  `agents/T13/a12/REPORT.md` under drift, and should be shown per platform if space allows.
- Messages from the engine are not repeated here. If an entry's text starts with a capital and
  names a file, a model or a URL, check a09 to a11 before adding it to TROUBLESHOOTING.
