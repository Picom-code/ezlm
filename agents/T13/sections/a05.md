# Keys and LAN mode

EZLM gives your model two things: an address and a key. The address is the same for every app that
uses it. The key is the password that proves a request is yours. This section shows where both are,
how to copy them, and what changes when you let other devices on your network use the model.

## Where the key is

Open EZLM and look at **Overview**, under **Connect with**. You get two rows, **URL** and **Key**
[1]. The key is shown masked, with its first nine characters and twelve dots, so you can recognise
it but not read it [2]. The full value is behind the **Copy** button [3].

The same two rows appear once at the end of setup, on the screen that says "Your AI is live", with
the line "Use this URL and key in any app that supports the OpenAI API." [4]

Every key EZLM makes starts with `ezlm-` and is followed by 40 random characters [5]. EZLM keeps the
key in `config.json`, inside the `.ezlm` folder in your home folder [6]. On Windows that is
`C:\Users\<you>\.ezlm\config.json`; on a Mac it is `~/.ezlm/config.json`. The file is readable only
by your own user account [7]. The key inside it is not encrypted, so anyone who can log in as you can
read it.

## Copy the key

1. Open **Overview**.
2. Find the **Key** row under **Connect with**.
3. Press **Copy**. The button says **Copied** for a moment [8].
4. Paste it into the app that asked for it.

Use **Copy** rather than reading the row: the masked text on screen does not show the full key [3].
In a terminal, `ezlm status` prints the URL, the LAN address and the full key, and `ezlm key` prints
just the key [9].

## Give each device its own key

**Keys** in the list on the left holds every key [10]. The line at the top explains the point: give
each device or app its own key, so you can revoke one without breaking the others [11].

- **New key** adds one. Type a name such as "Phone" and press **New key**; the name is only a label
  for you [12].
- The first key is the one EZLM writes into the apps it connects for you, and it is marked "used by
  connected apps" [13].
- **Rotate** replaces a key's value. Anything still using the old value stops working, and the apps
  EZLM connected are updated for you [14].
- **Revoke** deletes a key. It appears only when there is more than one key, because the server needs
  at least one [15]. If the key is the first one and apps are connected, EZLM moves those apps to the
  second key first [16].

Adding, rotating or revoking a key restarts the model server, because the list of accepted keys is
handed to the server when it starts [17]. The model reloads, which can take a minute, and a request in
flight at that moment fails. Do key work when nothing else is using the model.

## What LAN mode exposes

At the bottom of the **Keys** page, under **Network**, is a checkbox: **Let other devices on my
network use it (phones, other computers)** [18].

With it off, the model server listens on this computer only [19]. With it on, the server listens on
every network connection the computer has, and EZLM shows a **LAN URL** under the checkbox [20]. That
address is built from the computer's current network address, so it changes when you move between
networks [21]. If a device that used to work stops working, read the **LAN URL** in EZLM again and use
the new one.

LAN mode exposes the model's API and nothing else of EZLM. EZLM's own window and chat page listen on
this computer only [22], so another device gets the model, not your chat history or your files.

The key still applies. EZLM starts the model server with the key list, and the server refuses a
request that does not carry one of those keys [23]. A device on your network needs both the LAN URL
and a key.

One model serves everyone: the server runs with a single request slot, so a long request from a phone
makes your own request wait [24]. Turn the checkbox off when you are done.

The choice is remembered. It survives a restart and a model switch, so you set it once [25].

## The security trade-off in plain words

Off is the safe default. Only programs on your computer can reach the model, and nothing goes over the
network.

On means any device on the same network can reach the model if it has the key. The key is the only
lock, and the address is easy to guess on a home network. Treat the key like a password to your model:
do not paste it into a group chat or a public page.

The connection is plain HTTP, not HTTPS [26]. Nothing encrypts the traffic between your phone and your
computer, so anyone who can watch that network can read the key and the prompts. That is fine on a home
or office network you trust. On a cafe, hotel or airport network, someone else on the same network can
read it, and can then use your model.

Practical rules:

- Give each device its own key, so you can revoke one without touching the others.
- Turn LAN off when you are not using it. It is one checkbox.
- On a public network, leave it off.

## If another device cannot connect

- Use the **LAN URL**, not the address on the **Overview** page. `127.0.0.1` means "this computer" to
  whatever device opens it, so on a phone it points at the phone [27].
- An "unauthorized" or 401 answer means the key is missing, wrong or revoked. Copy it again from
  **Keys**.
- If the address does not open at all, check the checkbox is still on, then read the **LAN URL** again.
  The address may have changed.
- The first connection from another device may make Windows ask whether the model server can use the
  network. Allow it. EZLM does not create a firewall rule itself [28].
- Turning the checkbox on or off restarts the server. Wait for the model to finish loading before you
  test from the other device.
