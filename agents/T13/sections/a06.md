# Connecting OpenCode, Hermes and DeepSeek Harness

EZLM can put your model inside three apps:

- **OpenCode** is a coding agent that works in a terminal window.
- **Hermes** is a personal agent with tools and memory, also in a terminal.
- **DeepSeek Harness** is DeepSeek's agent harness, which runs in your browser.

You do not have to copy anything. Press **Connect**, and EZLM installs the app if it is missing, adds itself as a provider, and sends one real question to check that the app gets an answer. After that, **Open** starts the app already using your model.

## The one-click way

1. Make sure your model is running. On **Overview** the status should say **Ready** ("Waiting for requests from your apps"). If it says **The server is stopped**, press **Start server** and wait until it says **Ready** again. Connect checks that the app gets an answer, so it stays greyed out until the model is live.
2. Open **Connect** in the list on the left.
3. Click the tile of each app you want. A tile can be picked only when your model can use tools; Hermes also needs a model with a 64K context, and its tile cannot be picked when the model cannot have one.
4. Leave **Make it the default model in those apps** ticked unless you already use another model in that app and want to keep it. With the box ticked, EZLM's model becomes the app's own default, so it is used when you start the app yourself. Unticked, EZLM leaves that default alone; the **Open** buttons still open the app with EZLM's model.
5. Press the button that names your choice, for example **Connect OpenCode**. The first time, EZLM may download and install the app, which can take a few minutes.
6. Watch the tile. While EZLM works it shows what it is doing; when it finishes it says **✓ Connected and answering**. If it fails, the tile shows the reason, with **Show details** (the connection log) and **Report a problem**.
7. Press **Open OpenCode**, **Open Hermes** or **Open DeepSeek Harness (browser)** on Overview under **Use it**. The app opens in a new terminal window or in your browser, in the folder `EZLM Workspace` in your home folder, so a coding agent works on files there rather than across your whole home folder.

The check is a real conversation: EZLM asks the app to read a small file with its own file tool. A model that cannot use tools cannot be connected to these apps, and the tile says so; pick a model marked **Tools**, or use **Chat**.

## The URL and key, when an app asks for them

Most testers never need these, because Connect writes them into the app. When an app's own settings ask, use exactly what EZLM shows:

| Field | What to use |
|---|---|
| URL / Base URL | The **URL** row under **Connect with** on Overview. It looks like `http://127.0.0.1:8080/v1`. Press its **Copy** button rather than retyping it. |
| API key | The **Key** row beside it. The screen shows only the first nine characters and dots; press its **Copy** button to get the whole key. |
| Model | The entry EZLM added: **EZLM (local)** in OpenCode and DeepSeek Harness, provider **ezlm** in Hermes (its command-line name is **custom:ezlm**). The model's name ends in ** (EZLM)**. Do not type a model name by hand. |

Where to find them:

- **Overview > Connect with** shows the URL and the key used by connected apps, each with a Copy button.
- **Keys** in the left list shows every key. The first one is marked **used by connected apps**; the others are for phones, other computers and scripts.
- The last screen of the first-run wizard shows the same URL and key.

If you turned on **Let other devices on my network use it** on the Keys page, the Keys page also shows a **LAN URL**. On a phone or another computer use the LAN URL, not `127.0.0.1`: `127.0.0.1` always means "this computer". The LAN URL only works while EZLM is running on the machine that hosts the model.

The key is a password. Anyone who has it can use your model while EZLM is running. Do not paste it into a chat, a screenshot or a shared file. If it leaks, open **Keys**, press **Revoke** on that key, and give the app a new one.

## What EZLM writes, so you can find it later

| App | What appears in the app | Where EZLM writes it |
|---|---|---|
| OpenCode | Provider **EZLM (local)**; model **<your model> (EZLM)** | `opencode.json` or `opencode.jsonc` in `~/.config/opencode` (on Windows too, not `%APPDATA%`), plus `ezlm.key` beside it. The key is referenced as `{file:...}`, so it never sits inside the config file. `EZLM Workspace/opencode.json` picks the model for the terminal EZLM opens. |
| Hermes | Provider **ezlm** (the command line calls it **custom:ezlm**); model **<your model> (EZLM)** | `config.yaml` under `~/.hermes` (Windows: `%LOCALAPPDATA%\hermes`), or the profile `HERMES_HOME` names. Hermes stores the key in that file as `api_key`. |
| DeepSeek Harness | Provider **EZLM (local)**; model **<your model> (EZLM)** | One `cordis.patch.yml` in each profile under `~/.dsh` (`profiles/headless`, `profiles/web`, and `profiles/desktop` if it exists), plus the key in `~/.dsh/.env` as `EZLM_API_KEY`. |

You can read these files, but do not hand-edit EZLM's own entry: EZLM replaces it the next time it connects or updates that app. Put your own settings elsewhere in the file, and they are kept.

## After you change something

You do not need to reconnect after the usual changes. When you switch model, change the port, rotate a key or add a key, EZLM updates every app it connected. If an app's tile says **Points at an old address or key: EZLM fixes it when you open it**, just press its **Open** button: EZLM rewrites the app's settings and checks them before opening. If that does not clear it, press **Connect** for that app again.

## If EZLM's model does not show up

Connect adds the model but, with **Make it the default model in those apps** unticked, leaves the app's own default alone. That only matters when you start the app yourself, without EZLM's **Open** button: it then opens with its previous model. To switch it:

- **OpenCode:** open its model list and choose the provider **EZLM (local)**, then the model ending in ** (EZLM)**. OpenCode 2.x keeps this choice per project, so make it once in `EZLM Workspace`.
- **Hermes:** choose the provider **ezlm** (shown as **custom:ezlm** on the command line) and the model ending in ** (EZLM)** in its model list, or start it with `--provider custom:ezlm -m <model id>`.
- **DeepSeek Harness:** open its model settings and choose **EZLM (local)**, then the model ending in ** (EZLM)**.

The model id is the short name in the app's config, for example `qwen3.8-27b`; it is also the id the app's own model list shows.

## Common mistakes

| What you see | What it means | What to do |
|---|---|---|
| **Connect** is greyed out, or "Start your server first: connecting checks that the app gets an answer." | The model is not running, and Connect sends a real question to test it. | Press **Start server** on Overview and wait until the status says **Ready**. |
| The app answers "Incorrect API key" or 401. | The key was retyped from the dots on screen, or an old key was revoked. | Press **Copy** next to the Key row on Overview and paste it again. If you revoked the key, connect the app again so EZLM writes the new one. |
| The app answers "model not found" or lists no EZLM model. | The model name was typed by hand, or the app is pointed at a different EZLM model. | Choose the **EZLM (local)** entry, or press **Connect** again to have EZLM rewrite it. |
| The app cannot reach the URL, or gets a 404. | The URL was pasted without `/v1`, or the port changed after EZLM moved the server. | Copy the **URL** row again; it always includes `/v1` and the current port. |
| A phone or another computer cannot connect. | `127.0.0.1` means "this computer", so on another device it points at that device. | Turn on **Let other devices on my network use it** and use the **LAN URL** shown on the Keys page. |
| Hermes says it needs a 64K context. | Hermes refuses models with less than 64,000 tokens of context. | Press **Connect again** and EZLM gives the model the extra room (it may run slower), or pick a smaller model. |
| Hermes's tile is faded and cannot be picked. | Your model cannot reach 64K on this computer at all. | Press **Pick a smaller model**, then connect Hermes. |
| OpenCode says its history is from a newer version, its window cannot start, or it does not know a flag. | The OpenCode on your computer is older than the one EZLM tested. | Press **Connect**; EZLM installs and uses its own tested copy (2.2.5). |
| DeepSeek Harness opens a page that says "dsh web authentication required". | The browser page was opened without the one-time sign-in link `dsh web` prints, usually by visiting the address by hand. | Press **Open DeepSeek Harness (browser)** again, or reopen the link the terminal window printed. |
| DeepSeek Harness says another program is using its port. | Something else is listening on port 3080. | Close the other program, then open DeepSeek Harness again. |
| DeepSeek Harness says **EBADENGINE** or that Node.js is too old. | Its Node.js is older than 22.19.0. | Press **Connect**; EZLM installs its own Node.js and uses that. |
| OpenCode stops sending a key after you cleaned up your config folder. | `ezlm.key` was deleted; OpenCode 2.x then sends no key at all, without an error. | Press **Connect** to write the key file again. |
| You edited EZLM's entry in an app's config and your change disappeared. | EZLM owns that entry and rewrites it on every connect, model switch and key change. | Keep your own settings outside EZLM's entry; press **Connect** after changing anything EZLM manages. |

## If you would rather not use the buttons

The command line does the same work: `ezlm connect opencode hermes dsh` connects the apps you name, and adding `--default` makes EZLM's model the default in them. `ezlm doctor apps` prints each app's state, its config file, its last check and a quick launch check, without opening anything.
